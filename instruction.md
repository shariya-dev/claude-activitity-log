
## Phase 3: Nginx, HTTPS, cron

**File:** `/etc/nginx/sites-available/sixammonitor.com`. The values you change are marked `# ←`.
```nginx
server {
    listen 80;
    server_name sixammonitor.com www.sixammonitor.com;          # ← your domain
    root /var/www/sixammonitor/agent-dashboard/public;           # ← app folder + /agent-dashboard/public
    index index.php;
    client_max_body_size 4m;                                     # agent batches are ≤ 2 MB

    add_header X-Frame-Options "SAMEORIGIN";
    add_header X-Content-Type-Options "nosniff";

    location / { try_files $uri $uri/ /index.php?$query_string; }

    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.4-fpm.sock;             # ← PHP version
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
    }

    location ~ /\.(?!well-known).* { deny all; }                 # never serve .env

    location /downloads/ {                                       # agent installers (Phase 6)
        alias /var/www/sixammonitor-downloads/;
        autoindex off;
    }
}
```
```sh
sudo ln -s /etc/nginx/sites-available/sixammonitor.com /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo mkdir -p /var/www/sixammonitor-downloads
sudo nginx -t && sudo systemctl reload nginx

# HTTPS (free, auto-renewing)
sudo apt -y install certbot python3-certbot-nginx
sudo certbot --nginx -d sixammonitor.com -d www.sixammonitor.com --redirect -m admin@6amtech.com --agree-tos
```

**Cron** (`crontab -e` as `deploy`). The path is the only value to change:
```
* * * * * cd /var/www/sixammonitor/agent-dashboard && php artisan schedule:run >> /dev/null 2>&1
```

**Check it:**
```sh
curl -I https://sixammonitor.com/                            # 302 → https://sixammonitor.com/login
curl -s https://sixammonitor.com/api/agent/v1/sync/status    # {"success":false,"error":{"code":"unauthenticated",...}}
curl -I https://sixammonitor.com/.env                        # 403 or 404, never 200
```

**What keeps running from now on:** `nginx`, `php8.4-fpm`, `mysql` (systemd services) and the cron line. **Nothing else.** No queue worker, no `php artisan serve`, no Redis.

## Phase 4: First admin and dashboard settings

```sh
cd /var/www/sixammonitor/agent-dashboard
php artisan monitor:create-admin admin@6amtech.com --name="Admin"   # type a password, 12+ chars
```
Open **https://sixammonitor.com** → log in → **Tracking settings**, and set:

| Setting | Recommended first value | Notes |
|---|---|---|
| Categories | session, usage, project, model, device, account **ON** · prompt, git, network **OFF** | Prompt ON collects prompt text (encrypted, audited) |
| Initial sync range | `7d` | How far back a newly paired device sends (`1d`/`7d`/`30d`/`all`) |
| Sync interval | `120` s | How often agents send new data |
| Heartbeat interval | `300` s | How often agents check in |
| **Minimum agent version** | `1.0.0` | Must be ≤ the version you ship in Phase 5 |
| Retention | as your policy requires | Older data is pruned nightly |

Then **Users** → add other admins/viewers, and **Developers → Add developer** for each person.

## Phase 5: Build the agent release

The server address is **baked into the installer**. Build once per release; every developer uses the same file.

### 5.1 The two files you set

**`6am-agent/build-config.json`** (git-ignored). This is the only value that differs between local and production:

| | Local test build | **Production build** |
|---|---|---|
| File | `build-config.local.json` | `build-config.json` |
| `apiBaseUrl` | `"http://127.0.0.1:8100"` | `"https://sixammonitor.com"` |
| `channel` | `"dev"` (allows http to 127.0.0.1 only) | `"stable"` (https only, ignores env overrides) |

```json
{
  "apiBaseUrl": "https://sixammonitor.com",
  "channel": "stable"
}
```
Don't add `/api/agent/v1`; the agent adds it.

**`6am-agent/package.json` → `"version"`.** It's `"1.0.0"` for the first release. See Part C2 for later versions.

### 5.2 Build on a Mac
```sh
cd 6am-agent
npm ci
npm test && npm run typecheck && npm run lint           # must be green before a release

npm run build -- --target darwin-arm64 --config build-config.json   # Apple Silicon
npm run build -- --target darwin-x64   --config build-config.json   # Intel Macs

cat dist/darwin-arm64/app/build-config.json    # must show https://sixammonitor.com + "stable"
cat dist/darwin-arm64/VERSION                  # must show 1.0.0
```

**Package, signed and notarized** (values to change: identity name, Team ID, profile name):
```sh
# one time: store notary credentials in the keychain
xcrun notarytool store-credentials 6am-notary --apple-id you@6amtech.com --team-id ABCDE12345

packaging/macos/build-pkg.sh dist/darwin-arm64 1.0.0 \
  --sign "Developer ID Installer: 6AM Technologies (ABCDE12345)" --notarize-profile 6am-notary
packaging/macos/build-pkg.sh dist/darwin-x64 1.0.0 \
  --sign "Developer ID Installer: 6AM Technologies (ABCDE12345)" --notarize-profile 6am-notary
ls dist/macos/        # 6amAgent-1.0.0-arm64.pkg  6amAgent-1.0.0-x64.pkg
pkgutil --check-signature dist/macos/6amAgent-1.0.0-arm64.pkg   # "signed by a developer certificate"
```
Without an Apple account, drop `--sign` and `--notarize-profile`. The `.pkg` works, but users must right-click → Open.

### 5.3 Build Windows and Linux (optional)
```powershell
# Windows, with Inno Setup 6.3+
npm run build -- --target win-x64 --config build-config.json
powershell -NoProfile -ExecutionPolicy Bypass -File packaging\windows\build-installer.ps1 `
  -PayloadDir dist\win-x64 -Version 1.0.0            # optional: -SignToolPath ... -CertificateThumbprint <sha1>
# → packaging\windows\Output\6amAgent-1.0.0-x64.exe
```
```sh
# Linux
npm run build -- --target linux-x64 --config build-config.json
packaging/linux/build-packages.sh dist/linux-x64 1.0.0 x64      # → dist/packages/*.deb *.rpm *.tar.gz
```

### 5.4 Or: build everything with GitHub Actions
One time, in GitHub → repo → **Settings → Secrets and variables → Actions**:

| Type | Name | Example value |
|---|---|---|
| Variable | `AGENT_API_BASE_URL` | `https://sixammonitor.com` (the workflow writes a `stable` build-config from it) |
| Secret | `MACOS_INSTALLER_CERT_P12` | base64 of your "Developer ID Installer" `.p12` |
| Secret | `MACOS_INSTALLER_CERT_PASSWORD` | the `.p12` password |
| Secret | `MACOS_SIGN_IDENTITY` | `Developer ID Installer: 6AM Technologies (ABCDE12345)` |
| Secret | `APPLE_ID` / `APPLE_TEAM_ID` / `APPLE_APP_PASSWORD` | notarization login / `ABCDE12345` / app-specific password |
| Secret | `WINDOWS_CERT_PFX` / `WINDOWS_CERT_PASSWORD` | base64 `.pfx` / its password |

Then release by tag. **The tag must equal `package.json`'s version**:
```sh
git tag agent-v1.0.0 && git push origin agent-v1.0.0
```
The **agent-build** workflow builds macOS (arm64 + x64), Windows and Linux installers and attaches them to a draft GitHub Release `agent-v1.0.0`. Download them from there.

## Phase 6: Publish the installers
```sh
scp 6am-agent/dist/macos/6amAgent-1.0.0-*.pkg deploy@203.0.113.25:/var/www/sixammonitor-downloads/
# (plus the .exe / .deb / .rpm if you built them)
```
Download links then look like `https://sixammonitor.com/downloads/6amAgent-1.0.0-arm64.pkg`.

## Phase 7: Install on each developer's computer

1. Admin: **Developers → (person) → Generate pairing code**. The code looks like `ABCD-2345`, is single-use and valid for 15 minutes.
2. Send the developer the download link and, separately, the code.
3. Developer:
   - **macOS:** open the `.pkg` → a pairing page opens in the browser → enter the code.
   - **Windows:** run the `.exe` (no admin) → pairing page → enter the code.
   - **Linux:** `sudo apt install ./6am-agent_1.0.0_amd64.deb`, then as their own user `6am-agent pair` → type the code.
4. Verify on the developer machine (macOS shown):
   ```sh
   A="/Library/Application Support/6amAgent/current"; "$A/runtime/node" "$A/app/agent.cjs" status
   # Paired: yes · Backend: sixammonitor.com · Agent state: ok · Last success: <recent> · Service: running
   ```
5. Verify in the dashboard: **Devices** shows it *online*. Sessions, Projects and Token Analytics fill within a few minutes (the last 7 days on first sync).

## Phase 8: Go-live checklist
- [ ] `https://sixammonitor.com` has a valid certificate; `http://` redirects to https
- [ ] `/.env` returns 403/404; `APP_DEBUG=false`
- [ ] `APP_KEY` saved in the password manager; daily DB backup configured (Part E)
- [ ] Cron line present (`crontab -l`), and `php artisan schedule:list` shows `monitor:mark-offline` and `monitor:prune` with a next-run time
- [ ] Minimum agent version ≤ shipped version
- [ ] One real device paired and syncing
- [ ] Prompt tracking decision made (default OFF)

# Part C. After you change code

## C1. I changed agent code: test it locally before releasing

Your installed agent keeps running untouched; the test copy uses its own data folder.

```sh
cd /Applications/MAMP/htdocs/Claude-activity-agent/6am-agent

# 1. checks
npm test && npm run typecheck && npm run lint

# 2. build against your LOCAL backend (running: php artisan serve --host=0.0.0.0 --port=8100)
echo '{ "apiBaseUrl": "http://127.0.0.1:8100", "channel": "dev" }' > build-config.local.json
npm run build -- --target darwin-arm64 --config build-config.local.json

# 3. run the fresh build in a sandbox (separate data folder + file-based token, no Keychain, no service)
export AGENT_DATA_DIR=/tmp/6am-dev AGENT_CREDENTIAL_BACKEND=file
A=dist/darwin-arm64
$A/runtime/node $A/app/agent.cjs pair ABCD-2345     # a code from your local dashboard
$A/runtime/node $A/app/agent.cjs sync-now
$A/runtime/node $A/app/agent.cjs status
$A/runtime/node $A/app/agent.cjs diagnostics
tail -f /tmp/6am-dev/logs/*.log                     # watch what it does (Ctrl-C to stop)
```
- Optional, to test against sample data instead of your real Claude history: `export CLAUDE_CONFIG_DIR=/tmp/claude-sample` (a folder shaped like `~/.claude` with `projects/<dir>/<session>.jsonl`).
- Clean up the sandbox: `rm -rf /tmp/6am-dev`, then **Devices → Disable** the test device in the dashboard.

**To try it as a real install on your Mac**, package it and install over the existing agent. The pairing and data are kept, and the service restarts:
```sh
packaging/macos/build-pkg.sh dist/darwin-arm64 1.0.0
sudo installer -pkg dist/macos/6amAgent-1.0.0-arm64.pkg -target /
```

**End-to-end suite** (real agent + real backend + fault proxy, ~95 s):
```sh
cd ../e2e && npm ci && npm test
```

## C2. Releasing a new agent version

Example: `1.0.0` → `1.1.0`.

```sh
cd 6am-agent

# 1. bump the version: exactly these 3 files change
npm version 1.1.0 --no-git-tag-version                 # package.json + package-lock.json
sed -i '' "s/: '1.0.0';/: '1.1.0';/" src/cli/version.ts   # fallback used by unbundled runs/tests

# 2. verify
npm test && npm run typecheck && npm run lint
npm run build -- --target darwin-arm64 --config build-config.json
cat dist/darwin-arm64/VERSION                            # 1.1.0
dist/darwin-arm64/runtime/node dist/darwin-arm64/app/agent.cjs --version   # 6am-agent 1.1.0

# 3. commit
git add package.json package-lock.json src/cli/version.ts
git commit -m "chore(agent): release 1.1.0"
```

Then build the installers, **either**:
- **by hand:** repeat Phase 5.2/5.3 with `1.1.0` as the version argument, then Phase 6, **or**
- **by CI:** `git push origin main && git tag agent-v1.1.0 && git push origin agent-v1.1.0`, then download the installers from the draft release `agent-v1.1.0` and publish them (Phase 6).

**Roll it out:**
1. Developers install the new `.pkg`/`.exe`/`.deb` over the old one. No re-pairing: data and pairing are kept, and the service restarts on the new version.
2. Watch **Devices**: the agent version column shows who has updated.
3. When everyone is on 1.1.0, set **Tracking settings → Minimum agent version = `1.1.0`**. Stragglers then show *update required* and pause syncing; their data isn't lost and syncs after they update.

## C3. I changed backend or dashboard code

Locally first:
```sh
cd agent-dashboard
npm run build
php artisan test && vendor/bin/pint --test && vendor/bin/phpstan analyse && npm run lint && npm run types
git add -A && git commit -m "..." && git push origin main
```
Deploy to the server:
```sh
ssh deploy@203.0.113.25
cd /var/www/sixammonitor/agent-dashboard
php artisan down
git pull
composer install --no-dev --optimize-autoloader

```
Agents don't need anything during a backend deploy. While the server is down they keep their data and catch up afterwards.

## C4. Moving to another domain
1. Point DNS at the server; add the domain to Nginx `server_name` and run `certbot` for it.
2. `.env`: `APP_URL=https://new-domain.com`, then `php artisan config:cache`.
3. Agents: set `build-config.json` → `"apiBaseUrl": "https://new-domain.com"`, bump the version (C2), rebuild and publish.
4. Every device installs the new build **and pairs again** (the old build still points at the old domain).

# Part E. Commands, locations, troubleshooting

### Agent commands
`agent` = macOS `"/Library/Application Support/6amAgent/current/runtime/node" "/Library/Application Support/6amAgent/current/app/agent.cjs"` · Windows `& "$env:LOCALAPPDATA\Programs\6amAgent\runtime\node.exe" "$env:LOCALAPPDATA\Programs\6amAgent\app\agent.cjs"` · Linux `6am-agent`

| Command | Purpose |
|---|---|

### Troubleshooting
| Symptom | Fix |
|---|---|
| Agent **needs repair** | Dashboard: Devices → Generate re-pair code → `agent pair CODE` |
| **update required** | Install the newer build, or lower Minimum agent version. No data lost. |
| **device disabled** | Admin disabled it. It resumes ≤ 1 h after **Enable**. |
| **Claude data unavailable** | Claude Code never ran for this user, or it uses a custom `CLAUDE_CONFIG_DIR` |
| Pairing code rejected | Expired (15 min), used, or developer inactive. Generate a new one. |
| Agent can't reach server | On that machine: `curl https://sixammonitor.com/api/agent/v1/sync/status` must return JSON `unauthenticated`. Check DNS, the certificate, the firewall. |
| Dashboard 500 after `.env` edit | `php artisan config:cache` |
| Sync monitor health never changes; old data never pruned | Cron isn't running `schedule:run`. Check `crontab -l` and `php artisan schedule:list`. |
| Local: agent refuses `http://` | Only `dev` builds, only `127.0.0.1`/`localhost` |
| macOS "unidentified developer" | Sign and notarize (Phase 5.2) or right-click → Open |

### Privacy guarantees
The agent reads only Claude's data folder and `~/.claude.json`'s account block (and `.git/config`/`HEAD` only if Git tracking is ON), and never writes there. Prompt text is never read unless prompt tracking is ON. Disabling or uninstalling never deletes history.
